1. PROJECT OVERVIEW & ARCHITECTURE
----------------------------------------------------------------------------------------------------
Logx is a standalone Medical Device Telemetry Simulator designed to run independently (on a separate 
PC, laptop, virtual machine, or docker container) and stream live equipment health records, sensor 
telemetry, and failure codes to a central server (AURA AI Platform).

Architecture Topology:
+-------------------------------------------------------------+
| LOGx Standalone Client (Browser Web App or Python CLI)       |
|  - Simulates ICU, Radiology, Lab, OR, Ward Devices          |
|  - Generates Battery, Thermal, Voltage, Workload metrics    |
|  - Injects Anomaly & Failure Scenarios                      |
+-------------------------------------------------------------+
                            │
               HTTP REST POST / JSON Payloads
        Header: X-API-Key, Hospital-ID: demo-hospital
                            ▼
+-------------------------------------------------------------+
| Central AURA Backend Server (FastAPI / ML Pipeline :8000)   |
|  - Endpoint: POST /api/v1/ingest/telemetry                  |
|  - Real-time ML Anomaly Detection / Isolation Forest / XGB  |
|  - SHAP Explainability & Digital Twin Updates               |
|  - Central Dashboard Live Charts & Alerts                   |
+-------------------------------------------------------------+


2. CENTRAL SERVER INGESTION SPECIFICATION
----------------------------------------------------------------------------------------------------
Base Ingestion URL:
  http://<AURA_SERVER_IP>:8000/api/v1/ingest/telemetry

HTTP Method:
  POST

Required Headers:
  Content-Type: application/json
  X-API-Key: aura_live_ingest_key_2026
  Hospital-ID: demo-hospital (or target hospital identifier)

Telemetry JSON Payload Schema:
{
  "hospital_id": "demo-hospital",
  "device_id": "DEV000001",
  "device_type": "Ventilator",
  "department": "Intensive Care Unit (ICU)",
  "timestamp": "2026-08-16T00:20:00Z",
  "battery_health": 88.5,
  "temperature": 37.2,
  "load_percent": 65.0,
  "error_code": "OK",
  "operating_hours": 1420.5,
  "voltage": 23.8
}

Supported Error Codes & Injected Scenarios:
- "OK"            : Normal operational state (Healthy parameters: Battery >85%, Temp ~36.8C, Volt ~24V)
- "BAT_WARN"      : Low battery warning threshold (Battery ~25-32%)
- "BAT_CRITICAL"  : Critical battery failure (Battery ~12-22%, Voltage drops to ~17V)
- "TEMP_WARN"     : Elevated temperature warning (Temp ~39-42C)
- "TEMP_CRITICAL" : Thermal overheating failure risk (Temp ~46-52C, High load factor)
- "SENSOR_ERR"    : Sensor calibration drift or erratic noise
- "POWER_FLUC"    : Voltage power supply fluctuation (Voltage ~14-28V erratic)
- "SYS_RESET"     : Microcontroller reboot / freeze anomaly event

4. HOW TO RUN & EXECUTE
----------------------------------------------------------------------------------------------------
A. Running the Web Simulator:
   1. In terminal:
      python -m http.server 3000
   2. Open browser:
      http://localhost:3000
   3. Configure Target Server IP (default 127.0.0.1:8000) and click 'Start Log Stream'.

B. Running the Python CLI Generator:
   1. Ensure requests is installed:
      pip install requests
   2. Run continuous streamer:
      python external_hospital_log_generator.py --server 127.0.0.1 --port 8000 --interval 3.0
   3. Run with forced failure injection:
      python external_hospital_log_generator.py --scenario BAT_CRITICAL --interval 1.5
